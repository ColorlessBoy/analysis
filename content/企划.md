## 核心定位（一句话）

**所有答案被机器验证过的数学学习内容**——别人做不到的正确性背书。

## 单篇文章模板（统一格式）

```
标题: 《实分析》习题 X.Y.Z：一句话思路 + 机器验证证明
├─ 开场（情绪钩子：场景/故事/数据，1-2 段）
├─ 题目（原书陈述 + 为什么它坑人）
├─ 一句话提示（折叠）
├─ 思路：为什么这么做（折叠）
├─ 完整证明：文字数学证明 + Lean 代码块（可复制）
├─ 「机器验证」说明（这一步怎么被检查的 + 读者如何自己跑）
└─ 结尾钩子（下篇预告 + 互动问题："你在这本书哪题崩溃过？"）
```

## 情绪价值设计原则

1. **开场必是场景**：崩溃瞬间/顿悟瞬间/名人故事（素材库：B站 1273 赞评论、菲尔兹奖得主推翻自己证明、豆瓣 9.4 分、知乎 14.3 万浏览"自学难度"）
2. **每个"震撼点"一句话能说完**（如上表）
3. **结尾必有互动问题**——每篇文章 = 一道题的讨论串，这是"公开课病"的解药
4. **诚实是情绪的一部分**：Mathlib 墙篇、从零地图篇不回避问题，反而建立信任

## 第三层受众：开窍人群（每日一题形态）

逻辑题本身能吸引"开窍"的人——像数独、每日一题那样自带传播性。这类人不一定要学实分析，他们要的是**顿悟瞬间**（"哦——原来是这样！"）。

| 受众层 | 内容 | 规模 | 转化路径 |
|--------|------|------|---------|
| 开窍人群 | Lean 逻辑题（每日一题） | 大（数独人群） | 上瘾 → 好奇"证明" → 学 Lean 入门 |
| 新手池 | 系列 1（逻辑入门） | 中 | 学完 → 进入实分析 |
| 学习者 | 系列 2（实分析精讲） | 小但精准 | 留存 + 付费 |

**每日一题格式**：每天一道小逻辑题（如 `P → P → P` 变体、短路合取、`¬¬P` 系列），答案明天揭晓 + 机器验证。平台：知乎专栏/公众号/小红书日更，数据好的周更精讲。

## 运维策略：为什么它不会变成垃圾场（关键决策）

**"缺运维 → 题目垃圾场"是每日一题模式的经典死法。对策：把运维做成自动化，把治理做成规则。**

1. **内容供给自动化**：题目从仓库自动提取（124+ 习题 + 游戏关卡 + Mathlib 事实），AI 生成题目变体 → 人周审。日更的边际成本趋近于零——这是传统每日一题站做不到的
2. **判题自动化**：答案提交用 Lean 内核自动检查（LeetCode judge 模式）——运维里最贵的人力环节消失
3. **难度自动标定**：隐藏资产——`/Users/penglingwei/Documents/lean/analysis/.agents/experience/db.json` 记录了每道题形式化时的失败次数，**这就是机器测量的难度数据**（别的站只能用人工主观评级）。每日一题按难度桶自动排期
4. **垃圾场治理规则**：只保留三种内容形态（每日一题 / 每周精讲 / 每季企划），**不聚合、不转载、不投稿**——内容少而可控，宁缺毋滥。超出形态的一律不发布
5. **社区运维半自动**：自动化打卡/连击（streak）机制 + 每周一次直播答疑（人只做这一件重事）
