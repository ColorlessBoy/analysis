## 学完这课，你能…

- 读懂一段带中文注释的完整证明

## 热身（猜猜看）

下面是一段完整的 Lean 代码。先别看注释，猜猜它是干嘛的：

```lean
example {P : Prop} : P → P := fun hp => hp
```

猜不出来很正常——这就是本课的全部内容。学完再回来看，你会发现自己已经能读它了。

## 课文 1.1（逐行注释版）

```lean
example {P : Prop} : P → P := fun hp => hp
-- ①    ②    ③   ④   ⑤      ⑥        ⑦
```

| 位置 | 代码 | 读法 | 含义 |
|------|------|------|------|
| ① | `example` | "例题" | 我要声明一个待证明的命题 |
| ② | `{P : Prop}` | "P 是一个命题" | 引入一个命题变量 P（就像"设 x 是实数"） |
| ③ | `:` | "是" | 冒号后面是类型——我要证明的东西 |
| ④ | `P → P` | "P 蕴含 P" | 命题：如果 P 成立，则 P 成立 |
| ⑤ | `:=` | "定义为" | 冒号等号后面是证明（就是程序） |
| ⑥ | `fun hp => hp` | "lambda" | 一个函数：输入 hp，原样输出 hp |
| ⑦ | — | — | 机器检查：输入类型对了，输出类型对了，通过 |

**注意 ⑥**：`fun hp => hp` 读作"给我一个 P 的证据（hp），我把同一个证据还给你"。整个证明，就是一个函数。

## 课文 1.2（第一个"显然"）

```lean
example {P Q : Prop} : P → Q → P := fun hp _hq => hp
```

命题是"如果 P 且 Q 成立，则 P 成立"——你在高中数学里会写"显然"。在 Lean 里：

- 输入有两个：P 的证据 `hp`，Q 的证据 `hq`
- 要输出的：P 的证据——直接把 `hp` 还回去
- `_hq` 读作"下划线 hq"：**告诉机器"我知道这个输入用不上，故意的"**——就像语言里说"我知道这个词，但这句不用它"

**这段代码的每一个字符都有含义，没有一个是废话。**这就是机器验证的感觉：机器不会接受"显然"。

## 词汇表

| 符号 | 读法 | 含义 | 类比 |
|------|------|------|------|
| `example` | "例题" | 声明一个命题并证明它 | 造句 |
| `{P : Prop}` | "P 是命题" | 命题变量（花括号 = 自动推断，先不深究） | 设 P 是命题 |
| `:` | "是" | 类型标注：后面是类型 | 冒号后面是"是什么" |
| `P → Q` | "P 蕴含 Q" | 函数类型：从 P 的证据到 Q 的证据 | 函数签名 |
| `:=` | "定义为" | 后面是证明（程序本体） | 等号 |
| `fun x => ...` | "lambda" | 匿名函数：输入 x，返回 ... | 箭头函数 |
| `Prop` | "命题类型" | 命题的类型——真假的"类型" | 命题的世界 |
| `_hq` | "下划线 hq" | 故意不用的输入（下划线前缀 = 向机器声明） | 划掉不用的词 |

## 语法点：命题即类型（从课文里提取）

回看课文 1.1，你刚做了一件数学史上最深刻的事，只是没意识到：

**`P → P` 是"命题"，`fun hp => hp` 是"程序"——而它们被 `:=` 连在了一起。**

在 Lean 里，命题**就是**一种类型（Prop 类型的值），证明**就是**这个类型的值：

| 数学的世界 | 程序的世界 |
|-----------|-----------|
| 命题："P 蕴含 P" | 类型：`P → P` |
| 证明：由 P 推出 P 的方法 | 程序：输入 P 输出 P 的函数 |
| P 成立 | 类型 P 里存在一个值 |

**这就是"命题即类型"（Curry-Howard 对应）**——1920-30 年代 Curry 和 Howard 发现的定理，你刚亲手写了一遍。别急着"理解"它，本系列后面十课，每一课都是这句话的展开。

## 练习（答案折叠在每道题下面）

**练习 1 · 翻译**：把命题"如果 P 成立则 Q 成立"写成 Lean 的类型声明（不用写证明，只写类型）：

<details>
<summary>答案：</summary>

```lean
-- 类型：P → Q。证明（程序）留给你填
example {P Q : Prop} : P → Q := sorry
```

（`sorry` 是 Lean 里的"先跳过"标记——正式作品里禁用，练习里允许。下一题要写证明。）
</details>

**练习 2 · 仿写**：证明"如果 P 且 Q 成立，则 Q 成立"：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P → Q → Q := fun _hp hq => hq
```

输入 `_hp`（用不上，划掉）和 `hq`，输出 `hq`。
</details>

**练习 3 · 仿写（进阶）**：证明"如果 P、Q、R 都成立，则 P 成立"（三个输入，留一个）：

<details>
<summary>答案：</summary>

```lean
example {P Q R : Prop} : P → Q → R → P := fun hp _hq _hr => hp
```

三个输入，只用第一个，后两个划掉。
</details>

**练习 4 · 改错**：下面这段代码会报错。为什么？把错误信息念出来：

```lean
example {P Q : Prop} : P → Q → P := fun hp hq => hq
```

<details>
<summary>答案：</summary>

错误信息（大意）："`hq` 的类型是 `Q`，但这里需要 `P`"。
你承诺输出 P 的证据，却把 Q 的证据交了——**承诺（类型）和交付（程序）不匹配**。这就是 Lean 每天对你的要求：说到的必须做到。
</details>

## 总结

- 证明 = 程序：`P → P` 是类型（命题），`fun hp => hp` 是值（证明）
- 机器不认"显然"：每个符号都要有意义
- 用不上的输入，用 `_` 划掉

**下一课预告**：如果命题不是一个"固定的 P"，而是"对任意 n 都成立"呢？——`∀ n : ℕ, 0 ≤ n` 这个"无穷多个命题"的证明，会把你带到类型论最核心的地方：**依赖函数**。课文比这一课长一行，但思想深一个宇宙。
