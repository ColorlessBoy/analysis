> 《证明也是程序》系列 · 第 1 课 · 机器验证版

## 你有没有过"以为自己做对了"的时刻

我先说一件可能发生在你身上的事：

一道题，你做了四十分钟。思路清晰，每一步都有把握。做完合上书，自信满满。第二天对答案——错在第一步之后不久，你甚至没意识到自己是从哪里开始错的。

更糟的版本：**你永远没对答案。**你"以为"自己做对了，就这样带着一个错误的证明，继续往前走。直到某一天，在一个更深的定理里，那个错误突然冒出来咬你一口——那时候你已经忘了它是从哪来的。

这不是你笨。这是数学学习方式的一个结构性缺陷：**它不提供反馈。**老师会累，同学会心软，答案册会错（还经常找不到），而你自己——**你会骗自己。**你不是故意的，但人就是这样：写下一个"显然"的时候，心里那点不确定，会被自己悄悄按下去。

我受够了这个。所以我做了一件很笨的事。

## 我做了一件笨事

我把陶哲轩《实分析》——一本从自然数公理开始、一路修到测度论的教材——的**全部习题**，让一台机器逐个检查过。五万六千行。每一个证明，每一行推理，机器都检查过。没有一个"显然"被放过。

【这里补一个你真实的瞬间：你第一次发现"以为自己做对了"其实是错的——当时你是什么反应？】

做这件事之前，我以为自己是"学数学不太行"的那种人。做这件事之后我明白了，问题不在天赋，在别的地方。

那台机器叫 **Lean**。它做的事情只有一件，但做得比任何老师都彻底：

> **检查你的每一个推理步骤。错一个符号，整个证明拒收。**

它不累。它不会心软。它永远不信"显然"。而它给你的回报，是数学史上最稀缺的东西：**真实的反馈**。你写对了，它说对；你写错了，它告诉你错在哪个符号上——不是"你再想想"那种老师话，是精确到符号的判决。

这一课开始，我带你用它。

## 最小的一课：证明是什么

先解决一个你可能从来没被好好回答过的问题：**证明到底是什么？**

问自己：1 + 1 = 2，你怎么证明？

大部分人的第一反应是"这还用证明"——而这就是全部问题的起点。数学和物理、化学不一样：你不能说"你肉眼看看"，你不能做实验，你不能查资料。数学里的每一句话，都必须**只靠逻辑**从前面的话推出来。任何一步"凭感觉"的跳跃，都是非法的。

问题来了：谁来检查你的推理？——上面说过了，老师会累，你会骗自己。所以我们需要那个永远严格的裁判。

这就是 Lean 干的事。它把"证明"变成了一件可以检查的、实实在在的东西。现在你亲眼看一眼。

## 你写下的第一个证明

下面是一段完整的 Lean 代码。准确地说，是一个完整的证明：

```lean
example {P : Prop} : P → P := fun hp => hp
```

先别管那些符号。读一遍它的"人话"版本：

> 命题：如果 P 成立，则 P 成立。
> 证明：给我一个 P 成立的证据，我把同一个证据还给你。

`fun hp => hp` 就是那句话的代码形式：`fun hp`（给我一个证据 hp）`=>`（然后我）`hp`（把这个证据原样还给你）。

这就是一个完整的证明。它没有技巧，没有妙招——它只是诚实地完成了承诺：你说"P 蕴含 P"，我就证明给你看：无论 P 的证据是什么样，我都能把它还给你。

### 注意一个词：证据

刚才我一直说"证据"，不说"证明"。这是故意的：在 Lean 的世界里，`P` 是承诺（命题），而 `fun hp => hp` 是交付（证据）。**承诺和交付，是两回事。**

这个区分是整个系列最重要的一句话，先记住它：

> **命题是承诺，证明是交付。承诺和交付必须匹配。**

后面每一课都会回到这句话。现在，看第二个例子。

## 第二个证明：第一次"显然"

命题：如果 P 成立且 Q 成立，则 P 成立。

在数学书里，这句话通常配两个字："显然"。在 Lean 里，它长这样：

```lean
example {P Q : Prop} : P → Q → P := fun hp _hq => hp
```

两个输入：P 的证据（hp），Q 的证据（hq）。要交付的：P 的证据。所以我们把 hp 还回去。

注意 `_hq`——那个下划线。它的意思是："这个输入用不上，我知道，故意的。"

在数学书里，这一步被"显然"两个字盖住了。但"显然"底下藏着一个真实的决定：**哪个证据有用，哪个没用。**Lean 的好处是，它逼你把每个决定都做在明处——用不上的东西，要亲手划掉，不能假装它不存在。

## 你刚才做的事

把两个例子放一起看：

```
P → P        ← 命题（写在冒号右边）
fun hp => hp ← 证明（写在等号右边）
```

在 Lean 里，命题和证明是同一个东西的两副面孔：**命题是一种类型，证明是这个类型里的一个值。**这就是"命题即类型"——二十世纪数学里最深的思想之一，你刚刚用三十秒亲手写了一遍。

别急着理解它。这一课你只需要记住两件事：

1. **证明 = 诚实的交付。**承诺 P，就交付 P 的证据。不跳步，不"显然"。
2. **有一台机器检查你。**你写的每个证明，Lean 都会逐行检查。错一个符号，它拒收。

## 练习（答案折叠，先自己做）

**练习 1 · 翻译**：把命题"如果 P 成立则 Q 成立"写成 Lean 的类型声明（只写类型，不用写证明）：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P → Q := sorry
```

（`sorry` 是 Lean 的"先跳过"标记——正式作品里禁用，练习里允许。注意：你可以在练习里骗机器，但机器知道。）
</details>

**练习 2 · 仿写**：证明"如果 P 且 Q 成立，则 Q 成立"。提示：这次要交付的是 hq：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P → Q → Q := fun _hp hq => hq
```

P 的证据用不上，划掉（_hp）；Q 的证据就是答案，交付（hq）。
</details>

**练习 3 · 改错**：下面这段会报错。先自己读一遍，猜猜机器会说什么，再去 [Lean Web](https://lean.math.hhu.de/) 验证：

```lean
example {P Q : Prop} : P → Q → P := fun hp hq => hq
```

<details>
<summary>答案：</summary>

机器会说（大意）："`hq` 的类型是 `Q`，但这里需要 `P`。"

你承诺交付 P 的证据，却交了 Q 的证据。**承诺和交付不匹配。**

第一次被机器这么骂，是种特别的体验——它不像老师那样说"你再想想"，它精确地告诉你：错在哪个符号上。骂完你还得谢谢它。
</details>

## 一句话带走

> **你不需要天赋。你只需要不骗自己——以及一台不放过"显然"的机器。**

## 预告：这一课欠下的债

我们证明了"P 蕴含 P"——一个固定的命题。但数学里真正的命题长这样："**每个**自然数都不小于零"。

"每个"这个词（∀），下一课会告诉你一个吓人的事实：**它不是一句话，是一台机器。**而你会亲手把它写出来。

在那之前，去 [Lean Web](https://lean.math.hhu.de/) 把练习 3 的"错误代码"敲一遍，亲眼看看机器骂人的样子。这是本系列最重要的一次体验，不要跳过。
