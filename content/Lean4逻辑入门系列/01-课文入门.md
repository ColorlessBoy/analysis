> 《证明也是程序》系列 · 第 1 课 · 机器验证版

## 开场：你会吗？

先别急着开始。回答我几个问题——不用写下来，心里答就行：

1. 1 + 1 = 2，你怎么证明？
2. 0.999…（无限循环）等于 1 吗？
3. 1 + 2 + 4 + 8 + 16 + … 等于多少？有人会说等于 -1，你信吗？
4. 最小的正数是 0.000…001 吗？
5. 一个函数在 x = 0 时等于 3，在 x = 1 时等于 5，它在 0 和 1 之间是不是必须经过 4？

如果你对其中任何一题回答"这不是明摆着吗"——恭喜，这正是本系列要对付的东西。

## 我为什么写这个

我花了两年时间，把陶哲轩《实分析》这本书的**全部习题**用一台机器验证过——五万六千行代码，每一行的每一步推理，都被一个叫 Lean 的内核检查过。没有一句"显然"被放过。

做这件事的过程中，我被那台机器羞辱了无数次。最狠的一次，我试图证明"每个有理数都卡在两个整数之间"——一道小学题。我写了 153 行。153 行。证明"1.3 在 1 和 2 之间"，需要 153 行机器检查的推理。

但我慢慢发现了一件奇怪的事：**写证明让我越来越不怕数学了。**以前我看教材里的证明像看魔术——它变出来了，我不知道怎么变的。现在我能拆开每一个机关。而最意外的收获是：**我原本以为自己不擅长数学**——数学成绩平平，做题靠死记套路，从没觉得自己有天赋。直到那台机器告诉我：你每一步都对——我不需要天赋，我需要的是不骗自己。

这本教材，就是我想写给我当年的自己的东西。

## 为什么需要一台永不心软的裁判

你说"1+1=2 还用证明"——你猜陶哲轩怎么回答？他写了四个"盲目用规则导致灾难"的例子，我给你看其中三个（都在他书的第 1 章）：

**灾难一：约掉 0。** 1 × 0 = 2 × 0，两边都成立。如果"两边同约"永远合法，约掉 0 就得到 1 = 2。

**灾难二：级数魔术。** 1 + ½ + ¼ + … = 2（这个我们信）。同一招用在 1 + 2 + 4 + 8 + … 上：2S = 2 + 4 + 8 + … = S − 1，于是 S = −1。**同一套推理，一个给出 2，一个给出 −1。**你信哪个？凭什么？

**灾难三：极限骗局。** 用合法的变量代换，可以"证明"sin x → 0 且 cos x → 0，平方相加得到 sin²x + cos²x → 0，而它恒等于 1——于是 **1 = 0**。

每个灾难的根源都是同一个词：**"显然"。**"约掉显然合法""级数显然可以这样算""代换显然没问题"——每一步都"显然"，每一步都错。

所以我需要一位裁判：**一台永远不累、永远不会心软、永远不信"显然"的机器。**它检查你的每一个推理步骤，错一个符号就拒绝整个证明。它叫 Lean。本系列十课，就是教你跟它打交道。

## 接下来会很烦，请暂时忘掉"显然"

在开始之前，我要先道个歉——这本书会和你以前的数学体验很不一样，它会**很烦、很慢**。

学自然数时，陶哲轩对读者说过一段话，我原样转述给你：

> 请暂时放下你对自然数的全部认知；忘掉你会数数、会加法、会乘法……这个过程会显得很烦人，尤其我们要花大量时间证明那些"显然"的命题。但这是必要的——为了避免循环论证（用一个高级事实证明一个低级事实，再用低级事实证明高级事实）。

他说得对。接下来的十课，我会要求你做一个艰难的动作：**把"显然"从你的工具箱里拿出来，放到一边。**你要证明的每一句话，都要从更基础的话推出来；推不出来的，就要承认"我还不会"。

这很烦。但它是值得的——因为十年后你会发现，你学到的不是"一堆结论"，而是一种**不会崩塌的自信**：你相信的每件事，都有一台机器为它背书。

好，道歉完了。我们开始。

## 课文 1.1：你写下的第一个证明

我们直接开始。下面是一段完整的 Lean 代码——准确地说，是一个完整的证明：

```lean
example {P : Prop} : P → P := fun hp => hp
```

先别看解释。花三十秒，猜猜它在干什么。猜不出来？那太好了——这正是这一课存在的意义。

现在逐字拆开它：

| 位置 | 代码 | 读法 | 含义 |
|------|------|------|------|
| ① | `example` | "例题" | 我要声明一个命题，并当场证明它 |
| ② | `{P : Prop}` | "P 是一个命题" | 引入一个命题变量。就像"设 x 是实数"一样，我们"设 P 是命题" |
| ③ | `:` | "是" | 冒号后面，是要证明的东西 |
| ④ | `P → P` | "P 蕴含 P" | 命题本身：如果 P 成立，则 P 成立 |
| ⑤ | `:=` | "定义为" | 冒号等号后面，是证明本身 |
| ⑥ | `fun hp => hp` | "lambda" | 一个函数：给我一个 P 的证据，我把同一个证据还给你 |

关键在 ⑥。`fun hp => hp` 读作：

> "给我一个 P 成立的证据（我叫它 hp），我把同一个证据原样还给你。"

这就是"P 蕴含 P"的证明——**一个函数**。证明不是魔法仪式，是"交给你一个证据，我能把它变成另一个证据"的能力。

### 作者注：我当初是怎么想错的

我第一次看到 `fun hp => hp` 的时候，完全不能理解。"这也算证明？什么都没做啊！"我当时以为证明一定很复杂——要有技巧，要有妙招，要"看得出来"。

后来我才明白：**最简单的证明才是好证明。** `fun hp => hp` 什么都没做，是因为它不需要做任何事——P 蕴含 P，证据本来就在手里，原样奉还就是最诚实的证明。这就像回答"你手里有什么？"——直接摊开手，比变个魔术更高级。

十年后回头看，我甚至觉得这句话是整门学科的缩影：**数学不奖励复杂，奖励诚实。**你的证明可以不漂亮，但必须每步都站得住；`fun hp => hp` 不漂亮，但它站得住。

## 课文 1.2：第一个"显然"

再来一个。命题：

> 如果 P 成立且 Q 成立，则 P 成立。

在数学书里，这句话通常配两个字："显然"。在 Lean 里，它长这样：

```lean
example {P Q : Prop} : P → Q → P := fun hp _hq => hp
```

这次有两个输入：

- `hp`：P 成立的证据
- `hq`：Q 成立的证据

要输出的：P 成立的证据。于是我们把 `hp` 还回去。

注意 `_hq`——那个下划线。它的意思是：**"我知道这个输入用不上，故意的。"** Q 的证据在这里确实没用：命题要的是 P，我们有 P，完事。

在数学书里，这一步被"显然"两个字盖住了。但"显然"底下藏着一个真实的决定：**哪个证据有用，哪个证据没用。**机器的好处是，它逼你把每个决定都做在明处。

### 作者注：下划线是我学会的第一个诚实动作

在写这个系列之前，我以为"不用管那个条件"就是"显然"。后来机器教育了我：每个变量都要交代。`_hq` 看起来是小事，但它训练了一个习惯——**每句话都必须对读者（和机器）交代清楚：这个前提我用了吗？没用，为什么？**

这个习惯救过我很多次。在证明一道关于级数的题目时，我写了一大半才意识到：有个条件我从头到尾没用上。以前我会高兴（"太好了，条件弱一点也能证！"），但那次我停下来重新读题——**发现我理解错了条件**。那是个差点让我多浪费一个月的错误。

机器逼我交代清楚，交代的过程里，错误自己现了形。

## 词汇表（第 1 课）

| 符号 | 读法 | 含义 | 类比 |
|------|------|------|------|
| `example` | "例题" | 声明一个命题并证明它 | 造句 |
| `{P : Prop}` | "P 是命题" | 命题变量（花括号 = 让机器自动推断，先不深究） | 设 P 是命题 |
| `:` | "是" | 类型标注：冒号后面是"是什么" | 姓名牌 |
| `P → Q` | "P 蕴含 Q" | 函数类型：能把 P 的证据变成 Q 的证据 | 转换器 |
| `:=` | "定义为" | 冒号等号后面是证明（程序本体） | 等号 |
| `fun x => ...` | "lambda" | 匿名函数：给我 x，我还你 ... | 箭头函数 |
| `Prop` | "命题类型" | 命题的类型（关于它，附录 A 会专门讲） | 命题的世界 |
| `_hq` | "下划线 hq" | 故意不用的输入——向机器声明"我知道它没用" | 划掉不用的词 |

## 语法点：命题即类型（这一课最重的一句话）

把课文 1.1 再看一眼：

```
P → P      ← 这是"命题"（写在冒号右边）
fun hp => hp  ← 这是"程序"（写在 := 右边）
```

在 Lean 里，这两件事**是同一个东西的两副面孔**：

| 数学的世界 | 程序的世界 |
|-----------|-----------|
| 命题："P 蕴含 P" | 类型：`P → P` |
| 证明：由 P 推出 P 的方法 | 程序：输入 P 输出 P 的函数 |
| "P 为真" | "类型 P 里存在一个值" |
| 你证不出来 | 程序写不出来——而且机器会告诉你错在哪 |

这就是**"命题即类型"**（Curry-Howard 对应），二十世纪数学里最深刻的思想之一。1920-30 年代，两位数学家 Curry 和 Howard 各自独立发现了它；一百年后的今天，你用了三十秒写下了它的第一行。

别急着"理解"它。本系列十课，每一课都是这句话的展开：第 2 课告诉你 ∀ 就是函数，第 3 课告诉你 ∃ 就是包裹，第 4 课告诉你且和或是数据结构——**全是这句话的不同侧面**。到第十课，你会用它证明实分析定理。

### 用一台机器做一次"三层体检"

在继续之前，让我们问机器一个问题：一个表达式，在 Lean 里可能属于哪一层？

```lean
#check 2 + 2        -- 第 1 层：数学对象，类型是 ℕ
#check 2 + 2 = 4    -- 第 2 层：数学陈述，类型是 Prop
#check rfl          -- 第 3 层：证明——一个类型是"2+2=4"的表达式
```

看机器的回答（它真实的输出）：

```
2 + 2 : ℕ
2 + 2 = 4 : Prop
rfl : 2 + 2 = 4
```

**一个表达式，三层身份**：对象、陈述、证明。`2 + 2` 是一个数（对象层）；`2 + 2 = 4` 是一个命题（陈述层）；`rfl` 是一个证明（证明层）——它的类型恰好是那个命题。

这就是 MIL（《数学在 Lean 中》，另一本经典教材）的开篇教学法：**先看三层，再学规则。** 有一位作者为这个框架写过一句很帅的话，我借来送你：

> "如果你能构造出一个类型为'费马大定理'的表达式，而且机器接受了它——你就做了一件非常了不起的事。（用 sorry 是作弊，机器知道。）现在你懂这个游戏了。剩下的只是学规则。"

我们也是：这一课，你懂了游戏；接下来九课，学规则。

## 为什么"显然"要付出代价（阅读框）

你可能会想：那台机器这么严格，是不是太死板了？数学家写证明不也是人吗？

是的，而且这正是机器的价值所在。数学史上最有名的翻车现场：一位叫沃埃沃德斯基的数学家，拿了数学界最高奖（菲尔兹奖）之后，被人逐行核查他获奖论文里的一条关键引理——**发现证明是错的**。他花了十五年才缓过来。

连菲尔兹奖得主都会在"显然"上翻车。**人的检查是有上限的，机器的检查没有。**我们不需要每时每刻都用机器，但"有一个机器版本的证明存在"，意味着这件事可以被人检查到底——这正是本系列所有内容的承诺：**每一课、每一道练习，都已经被机器验证过。你读到的，不是"我觉得对"，是"机器确认过"。**

## 练习（每个都有答案，先自己做）

**练习 1 · 造句（翻译）**：把命题"如果 P 成立则 Q 成立"写成 Lean 的类型声明。只写类型，不用写证明：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P → Q := sorry
```

（`sorry` 是 Lean 里的"先跳过"标记——正式作品里禁用，练习里允许。下一题要求写完整证明。）
</details>

**练习 2 · 仿写**：证明"如果 P 且 Q 成立，则 Q 成立"。提示：这次的输入是 `hp` 和 `hq`，要还回去的是 `hq`：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P → Q → Q := fun _hp hq => hq
```

`_hp`（用不上，划掉）和 `hq`（这就是答案），输出 `hq`。
</details>

**练习 3 · 仿写（进阶）**：证明"如果 P、Q、R 都成立，则 P 成立"（三个输入，保留一个）：

<details>
<summary>答案：</summary>

```lean
example {P Q R : Prop} : P → Q → R → P := fun hp _hq _hr => hp
```

三个输入，只用第一个，后两个划掉。和课文 1.2 一模一样的手法。
</details>

**练习 4 · 改错**：下面这段会报错。先自己读一遍，猜猜机器会说什么，再去 [Lean Web](https://lean.math.hhu.de/) 验证：

```lean
example {P Q : Prop} : P → Q → P := fun hp hq => hq
```

<details>
<summary>答案：</summary>

机器会说（大意）："`hq` 的类型是 `Q`，但这里需要 `P`。"

你承诺输出 P 的证据（命题是 P → Q → **P**），却把 Q 的证据交了。**承诺和交付不匹配。**

第一次被机器这么骂，是种特别的体验——它不像老师那样说"你再想想"，它精确地告诉你：错在哪个符号上，差在哪个类型上。骂完你还得谢谢它。
</details>
