## 热身：第 1 课欠的一个问题

在第 1 课，我们写了：

```lean
example {P : Prop} : P → P := fun hp => hp
```

当时我们只说"`P` 是命题"，然后继续赶路。但你也许想过：**`Prop` 本身是什么？它有没有类型？**

这是一个好问题——它会一直追着我们到第 10 课毕业。今天补课。

## 课文 A.1：问机器

我们不知道答案。但有一台永不骗人的机器。问它：

```lean
#check Prop
#check Type
#check Type 1
#check Sort
#check Sort 0
#check Sort 1
#check Sort 2
#check ℕ
#check ℝ
```

机器回答（这是它真实的输出，一个字没改）：

```
Prop      : Type
Type      : Type 1
Type 1    : Type 2
Sort      : Prop       -- 注：单独写 Sort，它指的是 Sort 0
Sort 0    : Prop
Sort 1    : Type
Sort 2    : Type 1
ℕ         : Type
ℝ         : Type
```

## 课文 A.2：读懂回答——三件事

**第一件事：类型也有类型。** `Prop : Type` 读作"Prop 是一个类型"。`ℕ : Type` 读作"自然数是一个类型"。类型本身，也有自己的类型——就像文件夹里有文件夹。

**第二件事：类型排成梯子。** 把机器的回答竖着看：

```
Sort 0  （= Prop）    ：Sort 1 里的一个"种"
Sort 1  （= Type）    ：Sort 2 里的一个"种"
Sort 2  （= Type 1）  ：Sort 3 里的一个"种"
```

每一层都比上一层高。`Prop`、`Type`、`Type 1`……它们不是同一个世界的居民，是**层层叠叠的宇宙**（叫 Sort）。普通的东西（3、`fun hp => hp`）住在最下面；类型的类型住在上一层；类型的类型的类型住在再上一层……

**第三件事：没有最高的那一层。** 问机器 `universe u`（抽象一层宇宙）：

```lean
universe u
#check Sort u
#check Type u
```

回答：

```
Sort u : Type u
Type u : Type (u + 1)
```

**无论爬到哪一层，总有一层更高的。"所有类型的类型"不存在——这是一个永不封顶的梯子。**

## 阅读框：1902 年的一封信

你可能想问：为什么不能干脆说"所有类型都是类型"（Type : Type）？为什么非要爬梯子？

一百多年前，一位叫弗雷格的数学家，花了二十年写一套书，试图把整个算术建立在严格的逻辑上。快写完的时候，1902 年 6 月，一位年轻人给他写了封信。信里只有一个问题：

> "考虑'所有不包含自己的集合组成的集合'。它包含自己吗？——如果它包含自己，那它属于'不包含自己的集合'，所以它不该包含自己；如果它不包含自己，那它满足'不包含自己的集合'的定义，所以它应该包含自己。"

这个年轻人的名字叫罗素。弗雷格回信的第一句话是：

> "算术就这样崩坏了。"

二十年的工作，被一行话击穿。后来人们发现，问题出在一个共同点上：**"所有……的……"把全体装进一个容器，容器自己又成了全体的一员。**（就像"所有集合的集合"——它自己是不是一个集合？）

类型论修好这个洞的办法，就是你现在看到的梯子：**"所有类型的类型"被拆成"每一层类型的类型在下一层"。** 罗素的悖论在类型论里变成了一个编译错误——你可以亲手试：

```lean
-- 改错：Type 想装下自己
#check (Type : Type)
```

机器回答（报错）：

```
Type mismatch
  Type has type Type 1 but is expected to have type Type
```

**"所有类型的类型"不存在，不是因为我们做不到，是因为它本来就会让世界崩坏。**梯子不是麻烦，是防火梯。

## 词汇表

| 符号 | 读法 | 含义 | 类比 |
|------|------|------|------|
| `Sort` | "种/宇宙" | 类型的宇宙，层层叠叠 | 文件夹的文件夹 |
| `Prop` | "命题" | Sort 0：命题的世界 | 判断题的世界 |
| `Type` | "类型" | Sort 1：普通类型的世界 | 数据的世界 |
| `Type 1` | "类型一" | Sort 2：类型的类型的世界 | 元数据的世界 |
| `universe u` | "宇宙 u" | 抽象的层级（任意一层） | 第 n 层文件夹 |
| `#check` | "检查" | 问机器：这是什么类型 | 查字典 |

## 语法点：为什么 Prop 特殊

梯子的每一级都重要，但 Prop（Sort 0）特别。试一个实验：

```lean
#check ∀ P : Prop, P → P
```

机器回答：

```
∀ (P : Prop), P → P : Prop
```

读这个回答的第二遍：**"对所有命题 P 成立的命题"，它自己还是一个命题（Prop），没有升到 Type 去。**

这就是 Prop 存在的意义：**命题可以谈论所有命题，而不用爬到更高一层。** 数（ℕ）要谈论所有数，得去 Type 的上一层；但命题谈论所有命题，原地不动。这保证了一件事——**逻辑可以谈论逻辑**（"所有命题都蕴含自己"这句话，本身是个命题）。语言教材里，这叫"语法可以谈论语法"；数学里，这叫**直谓性**（impredicativity）——记住这个名字就行，你会在更深的书里再见到它。

## 练习

**练习 1 · 预测（翻译）**：先猜，再问机器验证——`#check True` 和 `#check P` 会输出什么？（提示：True 是"恒真"命题，在第 1 课没出现，但它是最简单的命题）

<details>
<summary>答案：</summary>

```lean
#check True   -- True : Prop
#check P      -- 报错：P 是未定义的符号——必须像课文里一样先声明 {P : Prop}
```

第一个：命题住在 Prop。第二个：练习"声明先行"——类型论里没有一个符号可以凭空出现。
</details>

**练习 2 · 仿写**：声明自己的抽象宇宙，然后问机器 `#check Sort u` 和 `#check Type u`（复制课文 A.2 的代码，把 `u` 换成 `v`，验证它同样成立）：

<details>
<summary>答案：</summary>

```lean
universe v
#check Sort v   -- Sort v : Type v
#check Type v   -- Type v : Type (v + 1)
```

名字（u 还是 v）不重要，梯子的形状不变。
</details>

**练习 3 · 改错**：课文阅读框里的 `#check (Type : Type)` 为什么报错？用自己的话解释（提示：`Type` 住在 `Type 1` 里，它装不下自己）：

<details>
<summary>答案：</summary>

`Type` 的类型是 `Type 1`，所以"把 Type 当作一个 Type 类型的东西"要求 `Type : Type` 成立——但 `Type` 在 `Type 1` 这一层，不在 `Type` 这一层。
**这行代码就是罗素悖论的化身**：任何"全体"想包含自己，机器都会说"层数不够"。
</details>

## 总结（整个系列的最后一页）

- 类型也有类型：`Prop : Type`、`Type : Type 1`……层层叠叠，没有顶
- 层级不是麻烦，是防火梯：1902 年那封信击穿了一个体系，类型论用"永不封顶"修好了它
- `Prop` 特殊：命题可以谈论所有命题而不升层（直谓性）
- 十课 + 一附录，你掌握的已经是一个完整的语言：**能读懂陈述、能写证明、能问机器、能看懂报错**
