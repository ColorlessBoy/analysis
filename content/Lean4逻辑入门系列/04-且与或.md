## 开场钩子

**"P 或 Q"比"P 且 Q"难证明——这不是你的错觉，是一个藏了一百年的结构差异。**

"且"像叠罗汉：两份证据往上摞。"或"像走独木桥：你必须先选一边，再交证据——而选择可能做错。今天的课文会告诉你：这两个字根本不是"连接词"，是两种数据结构。而且你会亲手体验一次"选错边被机器骂"。

## 学完这课，你能…

- 证明和拆解 `∧`（且）命题
- 证明和拆解 `∨`（或）命题
- 说出"或"为什么比"且"难证明

## 热身（复习旧词）

用第 3 课的词汇，证明"存在一个自然数大于 100"：

<details>
<summary>答案：</summary>

```lean
example : ∃ n : ℕ, n > 100 := ⟨101, by norm_num⟩
```

</details>

回顾：∃ 是包裹——`⟨见证者, 证据⟩`，当场交付。

## 课文 4.1（∧ 的拆开：配对的第一分量）

命题："如果 P 且 Q 成立，则 P 成立"。数学课会说"显然"。Lean 里：

```lean
example {P Q : Prop} : P ∧ Q → P := fun h => h.1
```

`h : P ∧ Q` 是一个**配对**——两份证据装在一起：`h.1` 是第一份（P 的证据），`h.2` 是第二份（Q 的证据）。**"且"的证据 = 配对，拆开用 `.1` / `.2`。**

`rcases` 写法（和 ∃ 的拆包同一个词——都是拆配对）：

```lean
example {P Q : Prop} : P ∧ Q → P := fun h => by
  rcases h with ⟨hp, hq⟩
  exact hp
```

`⟨hp, hq⟩`——同一个尖括号，从 ∃ 拆见证者，从 ∧ 拆证据。**你会越来越发现：类型论里就那几种动作，换个场景重复出现。**

## 课文 4.2（∧ 的组装）

反过来："如果 P 成立且 Q 成立，则 P 且 Q 成立"：

```lean
example {P Q : Prop} : P → Q → P ∧ Q := fun hp hq => ⟨hp, hq⟩
```

把两份证据装进一个配对，交付。**组装用 `⟨⟩`，拆开用 `.1`/`.2` 或 `rcases`——和 ∃ 一模一样的打包语法。**

## 课文 4.3（∨ 的引入：必须说明选了哪边）

命题："如果 P 成立，则 P 或 Q 成立"。直觉上"显然"。但你猜怎么着——**它比前几课所有的证明都多一个动作**：

```lean
example {P Q : Prop} : P → P ∨ Q := fun hp => Or.inl hp
```

`Or.inl`（in-left）读作"选左边"：**证明"P 或 Q"必须说明到底是哪个**——是 P 还是 Q。这里选 P，把 `hp` 交上去。`Or.inr`（in-right）是选右边。

tactic 写法（更常用）：

```lean
example {P Q : Prop} : P → P ∨ Q := fun hp => by
  left
  exact hp
```

`left` 就是 `Or.inl` 的语法糖——"我选左边"。**这就是"或"比"且"难的原因：且只要把两份证据都交出来，或必须做一个决定。**

## 课文 4.4（∨ 的消除：两种情况的会审）

"或"最难的是**用**。假设 `h : P ∨ Q`，而且 P 能推出 R、Q 也能推出 R，那么 R 成立。这叫"分情况讨论"，数学里每天在用：

```lean
example {P Q R : Prop} : P ∨ Q → (P → R) → (Q → R) → R := by
  intro h hp hq
  rcases h with hp' | hq'
  · exact hp hp'
  · exact hq hq'
```

| 位置 | 代码 | 含义 |
|------|------|------|
| ① | `rcases h with hp' \| hq'` | **竖线**：分叉！两种可能，两条路 |
| ② | `· exact hp hp'` | 情况一：h 是 P 这边 → 用 hp |
| ③ | `· exact hq hq'` | 情况二：h 是 Q 这边 → 用 hq |

**`rcases h with a | b` 的竖线 = "分叉"**：或的证据是一棵只有两个分支的树，你要两条路都走通。这就是"分情况讨论"在类型论里的样子。

## 词汇表

| 符号 | 读法 | 含义 | 类比 |
|------|------|------|------|
| `P ∧ Q` | "P 且 Q" | 合取：两份证据的配对 | 双人证言 |
| `h.1` / `h.2` | "第一/第二分量" | 取配对的第一/第二份证据 | 拆信封 |
| `P ∨ Q` | "P 或 Q" | 析取：二选一，附标记 | 单选题 |
| `Or.inl` / `Or.inr` | "选左/选右" | 或的引入：声明选哪边 | 举手站队 |
| `left` / `right` | "左边/右边" | `Or.inl/inr` 的语法糖 | 站队指令 |
| `rcases h with a \| b` | "分叉" | 或的消除：两条路都走 | 分情况讨论 |
| `·` | "点" | 当前分支的子证明 | 段落编号 |

## 语法点：积类型与和类型

把前四课连起来看，类型论其实只有两种数据结构：

| 结构 | 符号 | 别称 | 证明方式 |
|------|------|------|---------|
| **配对** | `P ∧ Q`、`∃ n, P n` | 积类型（product） | `⟨⟩` 组装，`.1`/`.2`/`rcases` 拆开 |
| **选择** | `P ∨ Q` | 和类型（sum） | `left`/`right` 选边，`rcases ... \|` 分叉 |

- "且"是**配对**：证据装一起 → 简单，因为信息只增不减
- "或"是**选择**：必须站队 → 难，因为要做出决定，而决定可能做错
- 配对和选择的另一个名字是**积**（×）与**和**（+）——写过程序的话：`P ∧ Q` 像元组，`P ∨ Q` 像枚举。**逻辑连接词不是语言，是数据结构。**

这就是为什么你小时候觉得"或"的证明比"且"别扭：不是数学难，是你一直在和一个必须做决定的数据结构打交道。

## 练习

**练习 1 · 翻译**：把"如果 P 且 Q 成立，则 Q 成立"写成 Lean 证明（提示：`.2` 或 `rcases`）：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : P ∧ Q → Q := fun h => h.2
```

</details>

**练习 2 · 仿写**：证明"如果 Q 成立，则 P 或 Q 成立"（课文 4.3 的镜像——这次选右边）：

<details>
<summary>答案：</summary>

```lean
example {P Q : Prop} : Q → P ∨ Q := fun hq => Or.inr hq
```

</details>

**练习 3 · 改错**：下面这段要证明"P 推出 Q 或 P"，会报错。为什么？

```lean
example {P Q : Prop} : P → Q ∨ P := fun hp => by
  left
  exact hp
```

<details>
<summary>答案：</summary>

错误信息："`hp` 的类型是 `P`，但这里需要 `Q`"。
你选左边（`left`）——选了左边就要证明 Q，但手里只有 P。**决定做错了：你应该选右边（`right`），手里有 P 就该选 P。**这就是"或"的代价：选择必须和证据一致。
</details>

## 总结

- `∧` = 配对：`⟨⟩` 组装，`.1`/`.2` 拆开
- `∨` = 选择：`left`/`right` 站队，`rcases ... |` 分叉
- 逻辑连接词 = 数据结构（积与和）
- "或"难在必须做决定——决定做错，机器就报错

**评论区题：你第一次学"或"的证明时，选错过边吗？说说你那次"错误选择"——所有被机器骂过的人，在这里集合。**

**下一课预告**：数学里最阴险的字——"不"。`¬P` 在类型论里不是"否定"，是 **`P → False`**（从 P 推出矛盾）。你会看到反证法的真面目：它不是技巧，是类型定义。还会遇到一个著名的思想实验：**在类型论里，"矛盾"是一种有类型的值吗？**
