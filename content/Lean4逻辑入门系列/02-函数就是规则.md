# 函数就是规则：∀ 到底是什么

> 《证明也是程序》系列 第 2 篇 · 依赖类型第一课 · 机器验证版

---

## 开场

你写过多少次这句话？

> "对任意 ε > 0，都存在 N，使得当 n ≥ N 时……"

大概率你第一次学它的时候，把它读成"对所有 ε 都成立"——然后心里默默补了一句"反正 ε 很小就对了"，接着开始背证明模板。

这不是你的错。"对任意"这三个字在中文里太日常了，日常到你会以为它和"对大家都好"是一个意思。**它不是。**

这一篇，我们要拆了"∀"。拆完之后你会知道：为什么 ε-δ 语言学不懂的人，往往不是不够聪明，而是没人告诉他 ∀ 到底是什么。

## 回顾：上一篇我们建立了什么

上一篇（《证明是一种程序》）我们建立了 Curry-Howard 对应：

| 数学 | 程序 |
|------|------|
| 命题 P | 类型 P |
| 证明 P | 类型 P 里的一个值 |
| P → Q | 函数：输入 P 的证据，输出 Q 的证据 |

我们做了第一道题：`P → P`，答案是 `fun hp => hp`——一个"原样返回"的函数。

现在有一个新问题。`P → P` 里的 P 是固定的——你证明的是"这个特定的 P 蕴含它自己"。但数学里真正厉害的命题长这样：

> **每个自然数都不小于它自己。**（n ≤ n，对每个自然数 n）

这不是一个命题，是**无穷多个命题**：0 ≤ 0、1 ≤ 1、2 ≤ 2……你不可能写无穷多个证明。那怎么办？

## 开窍点：∀ 是一台机器

类型论的回答干净得吓人：

> **"对任意 x，P(x) 成立"就是一个函数。它的输入是任意一个 x，输出是 P(x) 的证明。**

在 Lean 里，命题

```
∀ n : ℕ, 0 ≤ n
```

（每个自然数都不小于零）的"证明"长这样：

```lean
-- 对任意自然数 n，0 ≤ n
example : ∀ n : ℕ, 0 ≤ n := by
  intro n
  exact Nat.zero_le n
```

但先别看 tactic 版本——看它的**真面目**（term 模式，这才是它本来的样子）：

```lean
-- 真面目：一个函数！输入 n，输出"0 ≤ n"的证明
example : ∀ n : ℕ, 0 ≤ n := fun n => Nat.zero_le n
```

`fun n => Nat.zero_le n`——给你一个 n，还你"0 ≤ n"的证明。**∀ 不是一个"全称咒语"，是一台流水线机器**：任何 n 放进去，都能产出证明出来。

注意这里的怪事：`Nat.zero_le n` 的类型**取决于 n**。n = 0 时它是"0 ≤ 0"的证明，n = 5 时它是"0 ≤ 5"的证明。**输出的类型随输入变化**——这种函数叫**依赖函数**（dependent function），而整个类型论体系就是建立在这个"依赖"上，所以它才叫**依赖类型论**。同理，`rfl` 也是：`rfl` 是"某个东西等于它自己"的证明，放进去什么，就证明什么。

## 为什么这解释了你学不懂 ε-δ

陶哲轩《实分析》里的极限定义长这样：

> 序列 (a_n) 收敛到 L，如果 **对任意 ε > 0**，存在 N，使得对任意 n ≥ N，有 |a_n - L| < ε。

三个量词：∀ε，∃N，∀n。翻译成机器语言：

```
机器 ε: 你递进来任意一个 ε > 0
机器 N: 它必须还你一个 N（N 可以依赖 ε！）
机器 n: 对任意比你大的 n，证明 |a_n - L| < ε
```

**这是三台套在一起的机器，不是一个句子。**你背模板学不会，是因为你在背"句子"，而它其实是"机器"。一旦你开始问"我递 ε 进去，N 从哪来？"——你就真正懂了极限。

（这就是本系列叫《证明也是程序》的原因：**学分析的人卡住的地方，往往是卡在"机器"上，不是卡在数学上。**）

## 再练一道

**∀ x : ℚ, x ≤ x + 1**——每个有理数都不超过它自己加一。

先自己想，再展开。

<details>
<summary>提示：</summary>

这也是一台机器：输入任意 x，输出 x ≤ x+1 的证明。
</details>

```lean
example : ∀ x : ℚ, x ≤ x + 1 := by
  intro x
  linarith
```

term 模式真面目：

```lean
example : ∀ x : ℚ, x ≤ x + 1 := fun x => by linarith
```

`fun x => ...`：一台机器，输入 x，吐出一个不等式证明。`linarith` 是帮你算算术的——但记住，**`linarith` 这个名字只是包装，机器本身是 `fun x =>`**。上一篇说过：tactic 永远是你写的 λ 的语法糖。

## 机器验证：写错一次试试

把下面这行扔进 [Lean Web](https://lean.math.hhu.de/)（零安装）：

```lean
-- 故意写错：想用"x ≤ x"糊弄过去
example : ∀ x : ℚ, x ≤ x + 1 := fun x => by
  rw [show x + 1 = x by linarith]  -- 假的！
```

（这一条会报错——`x + 1 = x` 是假的，`linarith` 会拒绝。**机器不会因为你"听起来很有道理"就放过你。**）

## 结尾钩子

现在你知道了：∀ 是一台机器。那么反向的问题来了——

**"存在 x 使得 P(x)"（∃）对应什么？**

直觉告诉你：∃ 应该也是某种函数？不对——它恰恰是∀ 的反面，类型论里它是**一对数据**：一个具体的 x，加上"P(x) 成立"的证明。这就是下一篇《构造主义者宣言：存在 = 给出现场》的内容——也是 1900 年代数学界吵了三十年的话题。
