# 构造主义者宣言：存在 = 给出现场

> 《证明也是程序》系列 第 3 篇 · 存在量词 · 机器验证版

---

## 开场：一个"作弊"的证明

有一个著名的定理，数学界人尽皆知：

> **存在两个无理数 a、b，使得 a^b 是有理数。**

这个定理的证明，只用了三行：

> 考虑 √2^√2。
>
> 情况一：如果 √2^√2 是有理数，取 a = √2，b = √2，定理成立。
>
> 情况二：如果 √2^√2 是无理数，取 a = √2^√2，b = √2，那么 a^b = (√2^√2)^√2 = √2² = 2，是有理数，定理成立。

两种情况必居其一，所以……**存在**。

你发现哪里不对劲了吗？

**这个证明从头到尾，没有告诉我们 a 和 b 到底是什么。**它证明了"存在"，却拿不出任何一对具体的数字。数学课的裁决是：这就够了，证明合法。一百多年来，这个证明一直作为"非构造性证明"的经典教材——干净、优雅、令人恼火。

现在，让我们看看类型论怎么看待这个证明。

## 类型论：∃ 是一对数据

回顾第二篇：∀ 是一台机器。那 ∃ 呢？

在类型论里，命题

```
∃ n : ℕ, n > 5
```

不是一句话，是一个**数据结构**——一对（pair）：

```
（一个具体的见证者 n）+（n > 5 的证明）
```

**"存在 x 使得 P(x)" = 一对数据：先交出 x 本人，再交出 P(x) 的证明。**没有见证者，就没有"存在"。

在 Lean 里，证明"存在一个大于 5 的自然数"，就是把这堆数据当场交出来：

```lean
-- 见证者：6；证据：6 > 5
example : ∃ n : ℕ, n > 5 := ⟨6, by norm_num⟩
```

尖括号 `⟨⟩` 就是"打包"——把见证者和证明绑成一个包裹。`6` 是见证者，`by norm_num` 是证据。**这就是"存在"的完整交付。**

再看怎么拆包——从"存在"里取出见证者用：

```lean
-- 命题内部：拆开包裹，复用见证者
example (h : ∃ n : ℕ, n > 5) : ∃ m : ℕ, m > 3 := by
  rcases h with ⟨n, hn⟩
  exact ⟨n, by omega⟩
```

`rcases h with ⟨n, hn⟩` 把包裹拆开：n 是见证者，hn 是"n > 5"的证据。然后我们重新打包：同一个 n，证明它大于 3。

## 震撼点：那个"作弊"的证明，在类型论里被裁决了

还记得 √2^√2 那个证明吗？它的问题在类型论里一目了然：**它想打包一个包裹，但手里没有见证者**——它只有"见证者存在于两个候选之一"的推理。

1900 年代，数学界为这种事吵了三十年。有一派数学家（构造主义者/直觉主义者，领头的是布劳威尔）坚持：

> **"存在"必须意味着"我能拿出来"。**你证明存在一个 x，你就得给出 x 本人。证明"要么 P 要么 ¬P"，你就得说明到底是哪个。

主流数学界觉得他们不可理喻——证明存在就好了，管你怎么证的？

一百年后，Curry-Howard 给出了裁决：构造性证明 = **能编译的程序**；非构造性证明 = **编译不过**。布劳威尔的主张不是怪癖，是类型论里最朴素的要求：**类型 ∃ 要填满，就必须有值**。

在 Lean 里，"作弊"是可见的：如果你真的想从那个 √2^√2 证明里提取见证者，你必须调用选择公理（Classical.choose）——而且编译器会要求你标注 `noncomputable`，意思是："**这个函数不是算出来的，是赌出来的**"：

```lean
-- 非构造性提取：Classical.choose（选择公理的日常用法）
noncomputable def getWitness (h : ∃ n : ℕ, n > 5) : ℕ := Classical.choose h
```

`noncomputable` 四个字，就是类型论给非构造性证明贴的标签：**不是算出来的，是选出来的。**数学课本把它藏在"显然"，Lean 把它写在脸上。

## 你知道吗：Lean 里的两套逻辑

Lean 的内核是构造性的——上面的 `⟨6, by norm_num⟩` 不需要任何公理。但 Mathlib（标准库）默认提供经典逻辑：排中律（P ∨ ¬P）、选择公理都可直接用。

也就是说，你在 Lean 里可以**选择**自己的世界观：
- 构造性模式：每个"存在"都要给出现场
- 经典模式：`by_cases`、`Classical.choose` 随便用

这是数学史上唯一一个让你自己选逻辑体系的工具。选哪边，全看你愿意交多少"现场"。

## 机器验证：写错一次试试

把下面这行扔进 [Lean Web](https://lean.math.hhu.de/)（零安装）：

```lean
-- 故意写错：见证者不合格（3 并不大于 5）
example : ∃ n : ℕ, n > 5 := ⟨3, by norm_num⟩
```

你会得到一个错误：`unsolved goals ⊢ False`——**你交出的证据是假的，机器拒绝收货。**"存在"不是你说存在就存在的：见证者要合格，证据要成立，两个都过关，包裹才签收。

## 结尾钩子

现在你有了两件武器：
- **∀** = 一台机器（你递进去什么，它证明什么）
- **∃** = 一个包裹（见证者 + 证据，当场交付）

下一篇，我们要拆解数学里最日常的两个字——**"且"和"或"**。在类型论里，它们不是"连接词"，是两种截然不同的数据结构：一个是**配对**，一个是**选择**。到时候你会发现："或"比"且"难证明——这个问题藏了一百年。

先想一个问题：为什么证明"P 或 Q"时，你必须先说清楚是哪个？
