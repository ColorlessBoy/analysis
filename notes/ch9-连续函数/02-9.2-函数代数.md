# 02 · 9.2 函数代数：把函数变成"可以算的数"

> 陶哲轩《实分析》9.2 完整叙事 + 原文 + Lean 形式化对照
> One Big Idea：**给函数装上加减乘除，才能让"极限是值"变成"极限是可以分配进和式里的"。**

---

## 第一幕 · 动机：为什么"函数代数"值得单独一节

### 开场：一个你没意识到的前提

你认识很多函数：f(x) = x² + 3x + 5，g(x) = sin x · eˣ。它们长得像"式子"。所以当有人说"函数也能相加减"时，你心里大概想的是"当然能，真没废话"。

但这个直觉在 9.2 之前**还不是数学**——它只是一个待确认的约定。为什么？因为函数不是"式子"，它是**规则**：每个输入 x 指派一个输出 f(x)。"f + g"这个记号，是一个**新的函数**，它在每个点上取 f 和 g 各自取值的和：

```
(f + g)(x) := f(x) + g(x)     ∀ x ∈ X
```

这条公式同时回答了三个问题：f + g 的定义域是什么？值怎么算？ **它凭什么合法？**——因为实数的加法已经存在，逐点搬运过来就行。函数代数的一切，都是"把 ℝ 的运算逐点复制到函数上"。

### 反派登场：函数不一定是"友好的"

为什么需要重新定义而不只是"显然"？来看陶哲轩举的"敌人"：

```
f(x) := 1 若 x ∈ ℚ（有理数）
       0 若 x ∉ ℚ（无理数）
```

这个 Dirichlet 函数张嘴就是：和你见过的"代数函数"完全不是一回事——它不是"算"出来的，是**分阵营**式的。但它仍然是一个合法函数：每个 x 都有唯一输出。它也照样参与 f + g。

结论：**函数世界大到没必要"友好"；你不需要画得出它，只需要它可定义。** 9.2 的逐点运算，是给"所有函数"这个整体装上的算术，而不是只给多项式准备的。

### 本节只做一件事

把算术搬到函数上，然后走一个"章节内闭环"：定义 → 例 → 引理（/习题）。为什么值得写一整节？因为**第 9 章后面的每一个重要定理，都需要 function-level 的算术**——

- 9.3 的极限律：`lim(f+g) = lim f + lim g`——没有函数加法，这句话写不出来
- 9.4 的连续函数代数：连续函数 + 连续函数 = 连续函数
- 9.6 的 max/min：`max(f,g)` 的连续性直接继承

**没有 9.2 的"逐点复制"，后面每一行证明都要把点拆开重写一次。** 9.2 就是"给函数定义四则运算"的立法时刻。

## 2 · 揭示：逐点运算的八件套

Definition 9.2.1 一口气定义八个"函数上的运算"：

| 运算 | 定义（逐点） | Lean（`Section_9_2.lean`） |
|------|--------------|---------------------------|
| 加法 | (f+g)(x) = f(x) + g(x) | `add_func_eval` : (f + g) x = f x + g x |
| 减法 | (f−g)(x) = f(x) − g(x) | `sub_func_eval` |
| 乘法 | (f·g)(x) = f(x)·g(x) | `mul_func_eval` |
| 除法 | (f/g)(x) = f(x)/g(x)（要求 g(x)≠0） | `div_func_eval` |
| 最大值 | max(f,g)(x) = max(f(x), g(x)) | `max_func_eval` |
| 最小值 | min(f,g)(x) = min(f(x), g(x)) | `min_func_eval` |
| 数乘 | (c·f)(x) = c·f(x) | `smul_func_eval` |
| （限制） | f|X：重定义域 | （9.2 只提不定义——Lean 用区间直接表达） |

### 三个值得停留的"看头"

1. **除法有前提**：g(x) ≠ 0 对一切 x。若 g 有零点，f/g 在那些点不存在——就像 1/x 在 0。所以 9.3 的范例反复处理"g 在 x₀ 处为 0"的边角：`Convergesto.div` 需要 `hM : M ≠ 0`（`Section_9_3.lean:262`）。

2. **乘法和合成不是一回事**：`fg` 和 `f∘g` 是两种完全不同的操作。陶哲轩给过一个命题：`f·g ≠ f∘g` 一般。Lean 里 `Exercise_9_2_1` 系列逐个检验乘法分配律与合成的冲突（`Section_9_2.lean:54-77`）——这些 `Decidable` 是把"命题真/假"变成"可构造证明"的关键词。**逐点运算和复合运算的差别，是分析里最容易错的一步。**

3. **max/min 是可交互的**：`max(f,g)` 在每点取二者的较大值——这是 9.6 最大原理的"函数版本"的先导，也是 9.7 中值定理证明中的常用配角。

### 做法上的小机智：逐点操作 = 穷则变

在 Lean 里，这些定义几乎"免费"：因为 `f + g` 在 Mathlib 里**本身就是**逐点定义的（函数空间自动继承复数运算）。所以 `Section_9_2.lean` 的八个 `*_func_eval` 都只是 `rfl`——定义即证明。**这不是作弊：这是告诉你逐点运算"天然合法"。** 真正的功课在 9.3 之后：这个代数必须和极限"互相渗透"。

## 3 · 愿景：这一个小节，喂了整个章

9.2 之后，你带着"函数的代数"进入：

- **9.3**：`Convergesto.add/sub/mul/max/min/div` ——不写出 f+g，何谈 (f+g) 的极限律
- **9.4**：`ContinuousWithinAt.add/mul/div/comp` ——"连续函数带出连续运算"全部依赖 9.2
- **9.6**：`IsMaxOn.of_continuous_on_compact` 里的"最大值"是 `IsMaxOn` ——函数级的比较

一句话：**9.2 是第 9 章的"搬运工"——把实数的代数，无痛地变成函数的代数。** 它本身没有"反直觉"的门面，但它决定后面所有定理的证法（要不要拆点）。

## 原文（PDF 提取，公式略部分排版）

**Definition 9.2.1 (Arithmetic operations on functions)**: Given two functions f : X →R and g : X →R, we can define their sum f + g : X →R by the formula (f + g)(x) := f (x) + g(x), their difference ..., their maximum max(f, g)(x) := max(f (x), g(x)), their minimum, their product (fg)(x) := f (x)g(x), and (provided that g(x) ≠0 for all x ∈X) the quotient (f /g)(x) := f (x)/g(x). Finally, if c is a real number, we can define the function cf : X →R by (cf )(x) := c × f (x).

—— 关于两个世界："Just as numbers can be manipulated arithmetically, so can functions ... Given two functions f : X →R and g : X →R, we can define their sum."

—— 关于多领域："Strictly speaking, there is a distinction between a function f and its value f (x) at a point x. ... the derivative of f at 3 is 6, whereas the derivative of 9 is of course 0, so we cannot simply "differentiate both sides" of f (3) = 9 and conclude that 6 = 0."（这段笑话是 9.2 最好的"动机注"：如果你混淆 f 和 f(x)，微积分基础立刻崩盘。）

—— **Exercise 9.2.1** 的四问：`(f + g) ∘ h = (f ∘ h) + (g ∘ h)`；`f ∘ (g + h) = (f ∘ g) + (f ∘ h)`；`(f + g) · h = f · h + g · h`；`f · (g + h) = f · g + f · h`。其中两个是真的、两个是假的——你猜哪两个？答案见下节 9.3 的"极限律要区分满足"。提示：加法/乘法与复合的关系，取决于"线性"。

## Lean 追加

```lean
theorem add_func_eval (f g : ℝ → ℝ) (x : ℝ) : (f + g) x = f x + g x := rfl
```

逐点运算在 Lean 里就是 `rfl`——因为类型 ℝ→ℝ 自带测度族运算。这一行同时是"搬运工宣言"：算术从 ℝ 传导到函数，不丢失任何东西。
